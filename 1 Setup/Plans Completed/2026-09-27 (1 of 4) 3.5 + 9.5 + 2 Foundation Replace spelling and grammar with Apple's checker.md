## Purpose
Remove Sputnik's own spelling and grammar checker (3.5) and Grammar Help (9.5), and use the spelling and grammar checker that is built into macOS `NSTextView` instead.

## Success Condition
- `swift build` and `swift test` pass from the project root with no new warnings.
- `grep -rnE 'SpellingGrammarChecker|SpellCheckFileTypeGuard|SpellingCompletionProvider|GrammarHelp|GrammarSelectionAnalyzer|grammarHelp' --include=*.swift .` (without `.build/`) returns no results.
- Manual test in the app:
  - A `.txt` or `.md` file shows Apple's red dotted underline under a misspelled word. Right-click shows Apple's suggestions at the top of the menu.
  - Edit ▸ Spelling and Grammar ▸ "Check Grammar With Spelling" turns on Apple's green grammar underline. The setting stays after the app restarts.
  - A `.html`, `.json` or code file shows no spelling underlines.
  - HTML structural checking still shows its blue underline, and a click on it still opens the popover with Dismiss.
  - Help menu has no Grammar Help. Style Help still opens, and "More Context" on a plain-text selection opens Style Help.
  - A saved layout that contained a Grammar Help column opens without a crash and keeps its other columns.

## Decisions made in this plan (change them before you reply "go")
| Decision | Default in this plan |
|---|---|
| Style Help (9.9) | **Stays.** It came from Grammar Help, but it is a separate module. Plain text uses Style Help for More Context and Interaction. |
| Spelling ghost-text auto-complete (`SpellingCompletionProvider`) | **Removed.** Apple's word completion (Esc or ⌥Esc) stays available through `NSTextView`. |
| Which files get Apple's checker | Only `.txt` and `.md` (same as today). Code files do not get underlines. |
| Apple auto-correct (`isAutomaticSpellingCorrectionEnabled`) | **Off by default.** The user can turn it on in the Edit menu. |
| Settings ▸ Spelling tab | Keep it with two toggles only: "Check spelling while typing" and "Check grammar with spelling". Locale follows the macOS system setting. |

## Risks and Constraints
- **Foundation change (flagged).** Steps 3–5 change shared types. Build all modules after step 5, not only the editor.
- **Issues.md is append-only.** Only change the Status column of existing rows. Do not delete rows.
- **Apple's checker and syntax highlighting.** Apple draws its underlines with temporary layout attributes. `SyntaxHighlighter` writes normal attributes to `NSTextStorage`. They do not conflict, but test a large `.md` file for typing lag (SR-4).
- **The Edit ▸ Spelling and Grammar toggles must not use Apple's own `toggleContinuousSpellChecking(_:)`**, because that changes only the focused view and does not persist. Use the settings instead.
- **Stale matrix keys.** Old `WritingAssistMatrix` JSON has `instantCorrect.spelling`-style keys. The matrix stores cells as `[String: Bool]`, so old keys decode but must not crash `applies`. Step 11 (b) tests this.
- **Right-click menu.** `EditorTextView.menu(for:)` inserts Sputnik items at index 0. Check that Apple's spelling suggestions still show first when the click is on a misspelled word.
- Out of scope: Style Help changes, and anything in plans 2, 3 and 4.
