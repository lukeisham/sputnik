## Purpose
Give the ASCII Help system a **basic / advanced** distinction — in both the standard Help panel (9.2) and the "More Context" right-click lookup (2.7) — so users can browse and look up ASCII help by skill level instead of one flat corpus.

## Success Condition
- The ASCII Art Help panel (9.2) presents its topics split into **Basic** and **Advanced** (two headings or a segmented filter).
- Right-clicking a word in a `.asciiArt` document offers a **More Context: ASCII Art** submenu with **Basic** and **Advanced**, each opening the best-matching topic *at that level*.
- An older `index.json` without the new `level` field still loads (every topic defaults to `basic`), with no crash (SR-2).
- No new `HelpTopic` enum cases are added in Foundation — the single `.asciiArt` kind is retained.

## Design
**Terminology — basic / advanced** (user-facing; the module guide's "Tier 1 / Tier 2" map to these: *basic = Tier 1*, *advanced = Tier 2*).
- **Basic** = typed box-drawing diagrams: frames, lines, boxes, connectors, dividers (what auto-completion and the Library serve).
- **Advanced** = the Studio: image→ASCII conversion, density ramps, dithering, brightness/contrast, the editing tools.

**Resource model change.** Add a `level: ASCIIHelpLevel` (`basic` | `advanced`) field to `ASCIIArtHelpContent` and to each topic in `9 Resources/9.2 ASCII art Help/index.json`. Decode with a safe default of `.basic` so older index files still load (SR-2).

**New resource files (advanced topics).** Author new advanced `.md` topics — `advanced/image-to-ascii`, `advanced/density-ramps`, `advanced/dithering`, `advanced/brightness-contrast`, `advanced/line-art-edge-detection`, `advanced/editing-tools`, `advanced/opening-existing-art`, `advanced/saving-exporting`. Tag existing topics (drawing shapes, boxes, borders) as `basic`. (The edge-detection and open-existing topics track the matching Studio features.)

**Help panel UX (9.2).** The topic sidebar groups under two headings — **Basic** and **Advanced** — or a segmented Basic/Advanced filter above the list.

**More Context UX (2.7).** Right-clicking in a `.asciiArt` document offers the ASCII lookup split by level — a "More Context: ASCII Art" submenu with **Basic** and **Advanced**, each resolving to the best-matching topic *at that level*. The level filter is applied by the ASCII coordinator, **not** by adding Foundation `HelpTopic` cases.

## Steps

- [ ] 1. **Add a `level` field to the Help topic model**
   What: Add `ASCIIHelpLevel { basic, advanced }` and a `level` property to `ASCIIArtHelpContent`; decode from `index.json` with a default of `.basic` (SR-2 — older files still load).
   Why: A typed level is the single source the panel filter and the More Context split both read.

- [ ] 2. **Author the new advanced Help resource files and tag basics**
   What: Add `advanced/*` `.md` topics (image-to-ascii, density-ramps, dithering, brightness-contrast, line-art-edge-detection, editing-tools, opening-existing-art, saving-exporting) to `9 Resources/9.2 ASCII art Help/`; set `level` on every topic in `index.json` (existing diagram topics → `basic`).
   Why: These are the new resource files that make "advanced" reachable; without them the advanced level is empty.

- [ ] 3. **Group the Help panel by basic/advanced**
   What: In the ASCII Art Help panel sidebar, group/filter topics by `level` (two headings or a segmented Basic/Advanced control).
   Why: Lets users browse the standard Help split by skill level, per the requirement.

- [ ] 4. **Split "More Context" by level**
   What: Add a `level:` parameter to `ASCIIArtHelpCoordinator.bestMatch(for:)`/`search`; present the ASCII "More Context" item as a submenu with **Basic** and **Advanced**, each routing to a best match at that level. Keep the single `.asciiArt` `HelpTopic` kind (no new Foundation enum cases).
   Why: Delivers the basic/advanced distinction in the right-click lookup without expanding Foundation's help taxonomy.

## Risks and Constraints
- **SR-2 (decode safety):** `level` must decode with a `.basic` default — an older or partial `index.json` must never be rejected or crash the panel.
- **SR-1 (Foundation taxonomy):** do not add `.asciiArtBasic`/`.asciiArtAdvanced` `HelpTopic` cases — keep one `.asciiArt` kind and apply the level filter in the ASCII coordinator, so the rest of the help system is untouched.
- **Soft dependency on the Studio plan:** advanced-topic wording (dithering, brightness/contrast, editing tools) should match the Studio features delivered by `10 ASCII Studio Deepen ASCII Studio`. Draft in parallel; verify wording after those features land.
- **Terminology:** user-facing labels are **basic / advanced**; the guide's "Tier 1 / Tier 2" are the same concepts.
