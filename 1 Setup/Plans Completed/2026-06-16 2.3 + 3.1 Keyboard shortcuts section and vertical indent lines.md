## Purpose
Add a read-only **Keyboard Shortcuts** reference section to the Settings window and a **Vertical indent lines** toggle to the Editor settings tab that draws indentation guide lines in the text editor.

## Success Condition
- Settings window (⌘,) shows a seventh tab, **Shortcuts**, listing the app's keyboard shortcuts grouped by menu, each with a human-readable key combination.
- The **Editor** tab shows a new **Vertical indent lines** checkbox below "HTML syntax checking".
- Toggling **Vertical indent lines** on draws thin vertical guides at each indentation level in the text editor; toggling off removes them immediately. The setting persists across app launches.
- The project builds with no new warnings; the two new toggles round-trip through `UserDefaults` like every other `SettingsStore` field.

## Steps

### Part A — Vertical indent lines (the larger, riskier half)

1. **Add the `indentGuidesEnabled` setting to `SettingsStore`**
   What: In `2 Foundation/2.3 Settings/SettingsStore.swift`, add a `public var indentGuidesEnabled: Bool = true` under "Editor appearance", a `DefaultsKey.indentGuides` key, and a `setIndentGuidesEnabled(_:)` mutator that persists like `setCurrentLineHighlightEnabled`.
   Why: SR-1 — every editor setting is owned once in Foundation 2.3 and consumed by module 3; this mirrors the existing `currentLineHighlightEnabled` precedent exactly.

2. **Load the new key in `SettingsLoader`**
   What: In `2 Foundation/2.5 Persistence/SettingsLoader.swift`, read `DefaultsKey.indentGuides` into `indentGuidesEnabled`, defaulting to `true` when absent (match how `currentLineHighlight` is loaded).
   Why: Without a loader line the setting silently resets to its default every launch, breaking persistence (Success Condition).

3. **Add the editor-side flag and draw the guides in `EditorTextView`**
   What: In `3 Text Editor/3.1 Text/EditorTextView.swift`, add `var indentGuidesEnabled: Bool = false`. In `drawBackground(in:)` — after the current-line fill — when enabled, enumerate line fragments via `NSLayoutManager`, measure each line's leading-whitespace width using the editor font's space/character advance, and stroke a 1px vertical line at each indent stop (one guide per `indentWidth` columns) spanning the fragment height. Clip to `rect`; use a low-alpha colour derived from `NSColor.separatorColor` or `textColor.withAlphaComponent(~0.12)` so it adapts to light/dark.
   Why: `drawBackground(in:)` already owns background decoration and has the `layoutManager` + `textContainerOrigin` access needed (SW-3 seam is already justified here); reusing it avoids a second AppKit subclass and keeps the guides behind the glyphs.

4. **Compute indent width from the active editor mode**
   What: Derive the per-level column count (e.g. 4 spaces, or a tab's width) from the editor font's advance; tab-indented lines step one guide per tab, space-indented lines one guide per N columns. Keep this a small private helper on `EditorTextView` so the draw loop stays readable.
   Why: Indent guides are meaningless without a consistent column step; computing from the font keeps guides aligned with the rendered text at any font size (SR-4 — cheap, runs only in the draw pass).

5. **Propagate the toggle in `EditorView.updateNSView`**
   What: In `3 Text Editor/3.1 Text/EditorView.swift`, alongside the existing `currentLineHighlightEnabled` propagation block, set `edTextView.indentGuidesEnabled = settings.indentGuidesEnabled` and mark `needsDisplay = true` when it changes.
   Why: This is the established pattern for pushing a settings change into the live `NSTextView` so the toggle takes effect immediately without reopening the file.

### Part B — Editor tab checkbox

6. **Add the Vertical indent lines toggle to `EditorTab`**
   What: In `App-Sputnik/EditorTab.swift`, add a `Toggle("Vertical indent lines", …)` bound to `settings.indentGuidesEnabled` / `settings.setIndentGuidesEnabled($0)`, placed directly after the "HTML syntax checking" toggle and before the first `Divider()`.
   Why: Groups the new visual toggle with the other editor on/off appearance switches, matching the guide's documented Editor-tab layout.

### Part C — Keyboard Shortcuts section

7. **Create a `KeyboardShortcutCatalog` in Foundation**
   What: Add `2 Foundation/2.0 App Overview/KeyboardShortcutCatalog.swift` — a `public struct ShortcutEntry { let title, keys, group }` plus a `public static let all: [ShortcutEntry]` curated from the existing `.keyboardShortcut(...)` declarations in `FileMenuGroup`, `ViewMenuGroup`, `EditMenuGroup`, `FormatMenuGroup`, `HelpMenuGroup`, `SputnikMenuGroup`, and `SputnikCommands`. Format keys as glyphs (⌘ ⇧ ⌥ ⌃) for display.
   Why: SR-1 — a shared, single reference list belongs in Foundation, not in the App target. One file = one responsibility (SR-6).

8. **Build the `ShortcutsTab` view**
   What: Add `App-Sputnik/ShortcutsTab.swift` — a `Form`/`List` that groups `KeyboardShortcutCatalog.all` by `group`, each row a `LabeledContent(title) { Text(keys).monospaced() }`. Read-only; no `SettingsStore` mutation.
   Why: A reference section needs no editable state; reusing `LabeledContent` keeps it visually consistent with the other tabs.

9. **Register the tab in `SettingsView`**
   What: In `App-Sputnik/SettingsView.swift`, add `ShortcutsTab().tabItem { Label("Shortcuts", systemImage: "keyboard") }` after the Templates tab. Re-check the `.frame(width: 460)` is wide enough for the longest key string; widen only if it clips.
   Why: Surfaces the new section in the existing tabbed Settings scene with no new window plumbing.

### Part D — Documentation

10. **Update the 2.3 Settings Module Guide**
    What: Add `ShortcutsTab.swift` and the indent-lines toggle to the guide's Source Files table, ASCII diagram (Editor section + new tab), Technical Summary, and bump `last_updated`/`last_verified` to 2026-06-16. Note the new tab as the seventh section.
    Why: Working convention — the guide is the source of truth and must not drift (it currently documents six tabs).

## Risks and Constraints
- **Foundation change (module 2):** Steps 1, 2, and 7 touch Foundation, which every module depends on — additive only (new field, new loader line, new catalog file); no existing API changes. Flagged per the skill's Foundation rule.
- **Shortcut catalog is a *reference*, not the binding source.** The real shortcuts stay declared in the menu groups; `KeyboardShortcutCatalog` is a hand-maintained mirror. If a menu shortcut changes later, the catalog must be updated too — document this at the top of the catalog file so it isn't mistaken for the source of truth.
- **Indent-guide drawing runs in the display pass (SR-4):** keep the leading-whitespace scan O(visible lines) and avoid per-glyph layout queries beyond the line fragment loop; never iterate the whole document. Guides must clip to the dirty `rect`.
- **No force-unwraps (SR-2):** the whitespace/column math must `guard` against empty lines, missing `layoutManager`/`textContainer`, and zero-width fonts.
- Word-wrapped continuation lines should not start a new indent run — base guides on the line fragment's leading whitespace only.
