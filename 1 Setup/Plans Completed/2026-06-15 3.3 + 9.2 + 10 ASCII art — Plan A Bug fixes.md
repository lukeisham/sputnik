## Purpose
Fix twelve confirmed bugs and code-quality issues across the ASCII art modules so that the Studio canvas renders correctly, the undo stack is intact, edge detection captures all edges, and help-panel content loads safely — establishing a stable base before Plan B and Plan C add new features.

## Success Condition
- `ASCIIStudioView` canvas visually re-renders when any cell is edited, filled, aligned, or undone (observable in the UI).
- Clicking "Insert at Cursor" in the Studio successfully inserts into the editor after focus has moved to the Studio panel.
- Tab-accepted box frames are undoable with ⌘Z.
- Line-art conversion renders vertical lines (a vertical bar `|` source image) with non-zero intensity glyphs.
- Related Art in the help panel never shows duplicate entries.
- Opening a `.txt` file wider than 80 columns shows all characters with no right-side clipping.
- `swift build` (all three package targets) produces zero errors and zero warnings.

## Steps

- [ ] 1. **Fix `@State` → `@StateObject` for `ASCIIImageEditor` (ISS-117)**
   What: In `ASCIIStudioView.swift:39`, change `@State private var imageEditor = ASCIIImageEditor()` to `@StateObject private var imageEditor = ASCIIImageEditor()`.
   Why: `ASCIIImageEditor` is an `ObservableObject`; `@State` on a class reference does not observe `@Published` property changes, so the canvas, undo buttons, and edit toolbar are permanently stale after any edit.

- [ ] 2. **Track last-known editor text view in `ASCIIStudioCoordinator` (ISS-118)**
   What: Add `static weak var lastKnownTextView: NSTextView?` and `static func didBecomeFirstResponder(_ tv: NSTextView)` to `ASCIIStudioCoordinator`. In `EditorTextView.becomeFirstResponder()`, call `ASCIIStudioCoordinator.didBecomeFirstResponder(self)`. Update `activeTextView()` to fall back to `lastKnownTextView`. In `ASCIIStudioView`, disable "Insert at Cursor" and add `.help("Focus the editor first")` when `lastKnownTextView == nil`.
   Why: When the Studio panel is focused, `window.firstResponder` is a SwiftUI control, so `activeTextView()` returns nil and insert silently fails.

- [ ] 3. **Register box-drawing expansions with the undo manager (ISS-119)**
   What: In `BlockCompletion.apply(to:)`, before calling `storage.replaceCharacters(in:with:)`, use `textView.undoManager?.registerUndo(withTarget: textView) { tv in tv.textStorage?.replaceCharacters(in: expandedRange, with: payload.pattern) }` to make the expansion reversible. Capture `expandedRange` from the NSRange of the inserted frame string.
   Why: Box-drawing frame expansions accepted via Tab bypass the undo stack, breaking the editor's undo contract.

- [ ] 4. **Add vertical Sobel for full-gradient edge detection (ISS-120)**
   What: In `ASCIIEdgeDetector.detectEdges(in:width:height:)`, after the existing `CISobelH` pass, apply `CISobelV` (or use `CISobelGradients` if the deployment target is macOS 12+). Compute gradient magnitude per pixel as `√(Gx² + Gy²)`. Normalise the result to 0…1 before returning. If using Accelerate for the sqrt pass, retain the import; otherwise remove it (step 5).
   Why: `CISobelH` alone detects only horizontal gradients; purely vertical edges produce near-zero intensity and vanish from line-art output. This fix is also a precondition for the composite mode in Plan B.

- [ ] 5. **Remove dead `import Accelerate` (ISS-125)**
   What: Remove `import Accelerate` from `ASCIIEdgeDetector.swift` if step 4 does not use Accelerate. If it does, add a brief comment explaining the dependency.
   Why: A dead import adds build-graph noise and misleads readers into thinking Accelerate APIs are in use.

- [ ] 6. **Fix double art-load race in `ASCIIArtTopicContentView` (ISS-121)**
   What: Remove the outer `.task { await loadRelatedArt() }` on the `VStack` at line 201 of `ASCIIArtHelpPanelView.swift`. Add an `isLoadingArt` guard at the top of `loadRelatedArt()` so a second concurrent call (if it ever occurs) exits immediately.
   Why: Two concurrent tasks both call `loadRelatedArt()` before either writes results, bypassing the `resolvedArt.isEmpty` guard and appending duplicate entries.

- [ ] 7. **Cache `NSRegularExpression` as a `static let` (ISS-122)**
   What: Extract the regex inside `parsePlaceholders(in:)` to `private static let artPlaceholderRegex = try! NSRegularExpression(pattern: "@\\{art:([^}]+)\\}")`. Replace the inline `try?` construction with `Self.artPlaceholderRegex`. Add a comment noting why `try!` is safe (compile-time constant pattern).
   Why: Compiling the same regex on every `parsePlaceholders` call wastes CPU; the result is identical every time.

- [ ] 8. **Move markdown body disk read off `@MainActor` (ISS-123)**
   What: Inside `loadMarkdownBody(for:)`, wrap `String(contentsOf:url:encoding:)` in a `Task.detached(priority: .utility) { ... }.value` so the blocking read runs on the cooperative thread pool.
   Why: `String(contentsOf:)` is synchronous blocking I/O. The `.task` modifier runs on `@MainActor` by default, so the read currently blocks the main thread, violating SR-4.

- [ ] 9. **Auto-detect line width when opening a `.txt` file (ISS-124)**
   What: In `ASCIIStudioView.openTXT()`, compute `let maxLineWidth = result.content.components(separatedBy: .newlines).map(\.count).max() ?? 80` and pass it as `targetColumns`. Also set `targetWidth = Double(maxLineWidth)` so the Width slider reflects the loaded content.
   Why: The hardcoded `targetColumns: 80` silently clips any row wider than 80 characters, causing data loss.

- [ ] 10. **Make `blockCompletion` private (ISS-126)**
   What: Change `let blockCompletion: BlockCompletion` to `private let blockCompletion: BlockCompletion` in `ASCIIArtLanguageProvider.swift:17`.
   Why: The property is used only within `ASCIIArtLanguageProvider`. Internal access leaks a module implementation detail unnecessarily.

- [ ] 11. **Update 9.1 Module Guide — correct `id` type and remove `<!-- assumed -->` (ISS-127)**
   What: In `1 Setup/Module Guides/9 Resources/9.1 ASCII Library/guide.md`, change every `id: UUID` to `id: String`. Remove all `<!-- assumed -->` comments after verifying the statements against actual source. Set `last_verified: 2026-06-15`.
   Why: The guide is the source of truth; `id: UUID` vs `id: String` drift will mislead future contributors.

- [ ] 12. **Clarify `fill(_:)` label in the Studio UI (ISS-128)**
   What: In `ASCIIStudioView.editToolbar`, rename `Button("Fill")` to `Button("Fill non-space")` and add `.help("Replace every non-space character in the grid with the given character")`. Add a second `Button("Fill all")` that calls a new `ASCIIImageEditor.fillAll(_:)` method replacing every character including spaces, registered with the undo manager.
   Why: "Fill" implies full-canvas replacement; the actual behaviour (non-space only) surprises users.

## Risks and Constraints
- **SR-1 (step 2):** `EditorTextView` (3.1) calling `ASCIIStudioCoordinator.didBecomeFirstResponder` means 3.1 imports `ASCIIStudioModule`. If this creates an unwanted dependency, move the tracking to a Foundation 2.1 protocol (`protocol ASCIIInsertTarget`) and register the editor on launch via `AppState` instead.
- **`@StateObject` (step 1):** Canonical SwiftUI pattern for a class owned by the view. No parent init-site changes needed.
- **`CISobelV` / `CISobelGradients` (step 4):** Both single-channel filters are macOS 10.10+. `CISobelGradients` is macOS 12+. Check deployment target before choosing.
- **`try!` regex (step 7):** Safe for a compile-time-constant pattern. Add an explanatory comment so a future reader does not reflexively remove it.
