## Purpose

Add a Templates sub-module (2.10) so users can create new documents from saved boilerplate files with `{{placeholder}}` expansion, managed from the File menu and configured from a new Templates tab in Settings.

## Success Condition

- "Open Template ▶", "Save As Template ⌃⌘S", and "Remove Template ▶" are live in the File menu.
- A `.md` and `.html` starter template ship on first launch.
- Picking a template opens a sheet for any `{{key}}` placeholders; submitting opens a new untitled doc with the expanded content and the correct editor mode.
- Saving the current document as a template writes to the configured template folder and immediately appears in the menu.
- Removing a template deletes the file and removes it from the menu.
- A "Templates" tab in Settings shows the current folder path, a "Choose…" button to pick a new folder, and a "Reset to Default" button; changing the folder refreshes the template list immediately.
- All paths: no force-unwraps, no main-thread file I/O.

## Steps

- [x] 1. **Create `TemplateRecord.swift`**
   What: Define `struct TemplateRecord: Identifiable, Hashable, Sendable` with `id: URL` (the file URL), `name: String` (display name, filename without extension), and `fileExtension: String`. Derive `name` and `fileExtension` from the URL at init.
   Why: Gives the menu, sheet, and store a typed, `Sendable` value they can pass across actor boundaries (SW-1).

- [x] 2. **Create `TemplateStore.swift`**
   What: `actor TemplateStore` with a `static let shared` singleton. Holds `var directoryURL: URL` (settable by `AppState` when the user changes the folder in Settings). On first access, initialise `directoryURL` to `~/Library/Application Support/Sputnik/Templates/`; create the directory if absent; seed 2 starter templates (one `.md`, one `.html`) if the directory is empty. Implement:
   - `func setDirectory(_ url: URL) async` — updates `directoryURL`; called by `AppState` when `settings.templateDirectoryURL` changes.
   - `func templates() async -> [TemplateRecord]` — scans `directoryURL`, filters `.md`/`.html`/`.ascii`/`.txt`, returns sorted by name.
   - `func save(name: String, content: String, fileExtension: String) async throws` — writes the file; throws a `SputnikAlert` on name collision or I/O failure.
   - `func delete(record: TemplateRecord) async throws` — trashes the file via `FileManager.trashItem`.
   - `func rawContent(of record: TemplateRecord) async throws -> String` — reads file lazily; never holds content in memory beyond the call (SR-3).
   Why: Actor isolation ensures all file I/O stays off the main thread (SR-4) without bare `DispatchQueue` (SW-1). `directoryURL` is actor-isolated so Settings changes are applied safely without races.

- [x] 3. **Create `TemplatePlaceholderExpander.swift`**
   What: `enum TemplatePlaceholderExpander` (uninstantiable) with two pure static functions:
   - `func placeholders(in content: String) -> [String]` — scans for `{{key}}` tokens with `NSRegularExpression`; returns unique keys in order of first appearance; the pattern is a `static let` to avoid repeated compilation (cf. ISS-122).
   - `func expand(template: String, values: [String: String]) -> String` — substitutes each `{{key}}` with `values[key] ?? ""`.
   Auto-seeded defaults: `"date"` → `ISO8601DateFormatter` string of today's date (formatted as `YYYY-MM-DD`).
   Why: Pure, side-effect-free — easy to test; no actor overhead needed (SR-6).

- [x] 4. **Create `TemplatePlaceholderSheet.swift`**
   What: `struct TemplatePlaceholderSheet: View` that takes `request: TemplatePendingRequest` (see step 5) and an `onConfirm: ([String: String]) -> Void` callback. Shows one `TextField` per placeholder key (labels from the key name, dates pre-filled). "Open" button disabled until all non-date keys are non-empty. On confirm, calls `TemplatePlaceholderExpander.expand(template:values:)` and forwards the result. If no placeholders, auto-confirms immediately without showing.
   Why: Keeps the expansion UX in one self-contained view; sheet-level isolation means no coupling to `AppState` internals (SR-1).

- [x] 5. **Extend `AppState` with template state and actions**
   What: Add to `AppState`:
   - `var availableTemplates: [TemplateRecord] = []` — observable; refreshed by `refreshTemplates()`.
   - `var templatePendingRequest: TemplatePendingRequest?` — set when the user picks a template; drives the placeholder sheet (step 6). `TemplatePendingRequest` is a small `Identifiable Sendable` struct: `{ id: UUID, record: TemplateRecord, rawContent: String }`.
   - `func refreshTemplates() async` — calls `TemplateStore.shared.templates()`, writes result to `availableTemplates` on `@MainActor`.
   - `func openTemplate(record: TemplateRecord)` — reads raw content via `TemplateStore`, sets `templatePendingRequest` (triggers sheet); if zero placeholders, calls `openTemplateDocument` directly.
   - `func openTemplateDocument(content: String, fileExtension: String)` — creates a new untitled `DocumentSession` with the expanded content pre-loaded and the correct mode (`.markdown` for `.md`, `.html` for `.html`, `.text` otherwise); appends to active window; sets as active document.
   - `func saveCurrentAsTemplate(name: String)` — reads active document content, calls `TemplateStore.shared.save(...)`, then `refreshTemplates()`.
   - `func deleteTemplate(record: TemplateRecord)` — calls `TemplateStore.shared.delete(...)`, then `refreshTemplates()`.
   - `func applyTemplateDirectory(_ url: URL?) async` — resolves effective URL (url ?? default Application Support path), calls `TemplateStore.shared.setDirectory(_:)`, then `refreshTemplates()`. Called at launch and whenever `settings.templateDirectoryURL` changes.
   Call `refreshTemplates()` and `applyTemplateDirectory(settings.templateDirectoryURL)` on app launch (in `SputnikApp` or `AppDelegate`).
   Why: `AppState` is the single source of truth for observable cross-module state (SR-1, SR-2); menus and the sheet react to `availableTemplates` without polling. Bridging the Settings URL through `AppState` keeps `TemplateStore` free of a direct `SettingsStore` dependency (SR-1).

- [x] 6. **Update `FileMenuGroup.swift`**
   What: After "Open Recent ▶", add three new sections matching the user's spec:
   ```
   Divider()
   Menu("Open Template") {
       if appState.availableTemplates.isEmpty { Text("No Templates").foregroundStyle(.secondary) }
       else { ForEach(appState.availableTemplates) { r in Button(r.name) { appState.openTemplate(record: r) } } }
   }
   Divider()
   Button("Save As Template…") { saveAsTemplate(appState: appState) }
       .keyboardShortcut("s", modifiers: [.control, .command])
       .disabled(appState.editorCommandHandler == nil)
   Menu("Remove Template") {
       if appState.availableTemplates.isEmpty { Text("No Templates").foregroundStyle(.secondary) }
       else { ForEach(appState.availableTemplates) { r in Button(r.name) { Task { await appState.deleteTemplate(record: r) } } } }
   }
   ```
   Add `func saveAsTemplate(appState:)` to `MenuHelpers.swift` — presents an `NSAlert` with a text field for the template name, then calls `appState.saveCurrentAsTemplate(name:)` in a `Task`.
   Why: SwiftUI `Commands` observes `appState.availableTemplates` automatically — menus rebuild when the list changes (SR-4).

- [x] 7. **Attach `TemplatePlaceholderSheet` in `ContentView.swift`**

   Why: Sheet must attach to a live SwiftUI view, not to a `Commands` struct. `ContentView` is the correct host; it already holds `appState` (SR-1).

## Risks and Constraints

- **SR-1:** `TemplateStore` is Foundation-owned (module 2); other modules access templates only through `AppState` methods — never by importing `TemplateStore` directly.
- **SR-2:** Every `FileManager` call can throw — wrap all file I/O in `do/try/catch`; surface errors as `SputnikAlert` via `presentAlert`.
- **SR-3:** Template file content is read per `openTemplate` call and never cached in `AppState` or `TemplateStore` beyond the sheet's lifetime.
- **SR-4:** All `TemplateStore` methods are `async`; never call them on `@MainActor` without `await`.
- **SW-1:** No completion handlers; no bare `DispatchQueue.async`.
- **Keyboard shortcut conflict check:** `⌃⌘S` is currently unassigned in `FileMenuGroup`. Verify against `EditMenuGroup`, `ViewMenuGroup`, `FormatMenuGroup` before wiring it.
- **`ContentView.swift` is in the app target** (not the FoundationModule SPM package) — `TemplatePlaceholderSheet` must be importable from there. Since `ContentView` already imports `FoundationModule`, placing the sheet in `2.10 Templates/` (part of `FoundationModule`) is correct.
- **No `NSDocument`-based session model** — `openTemplateDocument` must match the existing `newUntitledDocument()` flow in `AppState`; do not introduce a new session lifecycle.
